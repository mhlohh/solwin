## 3. Dataset Purpose & Composition

The dataset is a **hybrid multi-domain dataset** combining two distinct message types:
1. **Customer Support Inquiries (~99.3%, 28,742 rows):**
   - General e-commerce complaints regarding orders, returns, reverse pickup, refunds, product quality, and agent behavior.
   - `subject` is empty (`""`).
   - `intent` maps to customer service workflows (e.g. `Reverse Pickup Enquiry`, `Return request`, `Delayed`).
   - `issue` contains composite details (often `<intent> - <message/specifics>`).
2. **Security & Phishing Attack Samples (~0.7%, 200 rows):**
   - Explicit attack vectors containing email subjects, phishing URLs, malicious attachments, and credential harvesting lures.
   - `subject` is populated (e.g. `"Urgent: Account Verification Required"`, `"Invoice #3921 Overdue"`).
   - `intent` reflects security threat classes (`Credential Harvesting`, `Malware Delivery`, `Financial Scam`, `Security Notification`, `Malware Attachment`).

| `Refund Enquiry`, `Refund Related Issues`, `Online Payment Issues`, `Payment related Queries` | `PAYMENT_BILLING` | **PARTIAL MATCH** | Map all refund & payment queries to `PAYMENT_BILLING` |

  - `Credential Harvesting` $\rightarrow$ `"PHISHING"`
  - `Malware Delivery` $\rightarrow$ `"PHISHING"`
  - `Malware Attachment` $\rightarrow$ `"PHISHING"`
  - `Fraudulent User` $\rightarrow$ `"SUSPICIOUS_MESSAGE"`
- `SocialEngineeringTechnique`:
  - `URGENCY`, `CREDENTIAL_HARVESTING`, `OTP_REQUEST`, `IMPERSONATION` are accurately extractable via regex heuristics in Solwin's `SocialEngineeringDetector`.

## 6. Required Adapter Logic (In-Memory Transformation)

To ingest the dataset into Solwin in a future phase without modifying the original read-only files, an adapter pipeline should perform:

1. **Record Deduplication & Cleaning:**
   - Filter out exact duplicate rows.
   - Clean whitespace and trim fields.
   - Handle missing messages (3 records have `NaN` / empty strings).
2. **Synthetic ID & Reference Generation:**
   - Generate deterministic UUIDv5 (using namespace + message hash) or UUIDv4 for `Conversation` and `Message`.
   - Generate stable `conversation_reference` (e.g. `REF-SHIFA-<index>`).
3. **Intent-to-Enum Normalization:**
   - Map the 65 distinct textual `intent` values to `ComplaintCategory` or mark for security threat creation.
4. **Channel & Customer Normalization:**
   - Detect if `subject` exists: if so, set `channel = ConversationChannel.EMAIL`; otherwise `ConversationChannel.TICKET`.
5. **Threat Auto-Classification:**
   - For records where `intent` is security-related (e.g., Credential Harvesting, Malware Delivery), extract URLs from message body and associate with Solwin's `Threat` model.

## 7. Duplicate & Identifier Findings

- **No Native Identifiers:** The dataset contains no unique identifiers.
- **No Timestamps:** All records lack temporal data. An ingestion pipeline would assign `datetime.now(timezone.utc)` or historical synthetic timestamps.
- **Duplicate Volume:** 
  - 7,337 full row duplicates out of 28,942 records.
  - Recommended deduplication key: `(hash(message), hash(subject), intent, issue)`.
